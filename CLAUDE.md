# Highway Lords

Unity **6000.3.1f1**, 2D. Жанр: tower defense + глобальна мапа з захопленням аванпостів + польові битви.

---

## Правила роботи (обов'язкові)

### 1. Мова
Спілкування з розробником — **українською**. Коментарі в коді — українською або англійською (як у наявному коді). Імена типів, полів і методів — англійською.

### 2. Нічого не створювати в рантаймі
Усі об'єкти, компоненти та UI мають існувати заздалегідь — на префабах або в сцені, налаштовані в інспекторі.

**Заборонено в рантайм-коді:**
- `new GameObject(...)`
- `gameObject.AddComponent<T>()`
- `DestroyImmediate(script)` / зривання компонентів з інстансу
- побудова UI-ієрархії кодом

**Дозволено:**
- `Instantiate(prefab)` — створення екземпляра готового префаба
- `SetActive()`, зміна полів, увімкнення/вимкнення компонентів
- генерація контенту **в едіторі** через скрипти в `Assets/Editor/` (це edit-time, не рантайм)

Якщо потрібен новий об'єкт у рантаймі — спершу робимо префаб із усіма потрібними скриптами, потім інстансуємо його.

### 3. Порядок в асетах
- Нові асети кладемо у відповідну тематичну папку, **ніколи в корінь `Assets/`**
- Один тип контенту — одна папка (не плодити `animations/`, `anim2/`, `anim3/`)
- Імена файлів осмислені: `Knight_Attack.anim`, не `1_0.controller`
- Скрипти по підпапках за призначенням, не купою в `scripts/`

### 4. Порядок в ієрархії
- Кореневі об'єкти сцени групуються за призначенням (менеджери, оточення, точки спавну, рендеринг, UI)
- Не додавати нові кореневі об'єкти без групи
- Імена унікальні та осмислені (не два корені з ім'ям `Map`)
- Усередині `Canvas` — поділ на HUD / Panels / Overlays, а не 40 дітей в один рівень

### 5. Перевірка змін
У середовищі Claude **немає Unity й .NET** — скомпілювати чи запустити гру неможливо. Тому:
- код і налаштування пише Claude, компіляція й перевірка в редакторі — за розробником
- зміни в ієрархії та масові зміни асетів робляться **через Editor-скрипти з меню**, а не прямою правкою YAML сцен (щоб не ламати GUID і не псувати сцени)
- правка `ProjectSettings/*.asset` і дрібних полів у `.asset` допустима, але завжди з поясненням, як відкотити

## Структура проєкту

### Сцени (`Assets/Scenes/`)
| Сцена | Роль |
|---|---|
| `BootScene` | точка входу, перехід у Main |
| `Main` | головна: TD-оборона замку + глобальна мапа + усі панелі |
| `SiegeBattleScene` | польова битва при атаці на аванпост |

### Ключові скрипти (`Assets/scripts/`)
| Скрипт | Роль |
|---|---|
| `GameManager` | центральний стан гри, економіка, апгрейди, UI оборони (**god-object, 3800+ рядків — поступово розбиваємо**) |
| `BattleManager` | бій у `SiegeBattleScene` |
| `CampaignManager` | панель підготовки атаки на аванпост |
| `CampaignUnit` | AI юніта в польовій битві |
| `MapNode` / `MapMarkerVisuals` | вузол глобальної мапи |
| `CrossSceneData` | статичний перенос даних між сценами |
| `QuestManager`, `ChestManager`, `CodexManager`, `TavernManager`, `SkillManager` | підсистеми меню |
| `SoundManager`, `WeatherManager`, `CameraController` | презентація |

Юніти оборони: `Knight`, `Archer`, `Spearman`, `Cavalry`, `WallArcher`, `CrossbowTower`
Юніти атаки: `Guard`, `EnemyArcher`, `EnemySpearman`, `EnemyHorse`, `EnemyElephant`, `Boss`, `BatteringRam`

## Конвенції коду

- Доступ до менеджерів через `Instance` (singleton), **завжди з перевіркою на `null`**
- Пошук юнітів — через реєстри в менеджерах, **не** `FindObjectsByType` у рантайм-циклах
- Перед використанням елемента з колекції знищуваних об'єктів — перевірка `!= null`
  (знищений `MonoBehaviour` кидає `MissingReferenceException`, а не повертає `null` при доступі до поля)
- Нові стати юнітів і ціни — в одне джерело, не дублювати числа по кількох менеджерах

## Відомі борги (контекст для рішень)

- Стати юнітів прописані хардкодом у трьох місцях (`GameManager`, `CampaignManager`, `BattleManager`) і числа розходяться
- 8 скриптів юнітів дублюють ~90% логіки — потрібен спільний базовий клас
- Збереження на 53 ключах `PlayerPrefs` замість одного серіалізованого сейву
- Немає пулінгу для стріл, крові та damage popup
- `CrossSceneData.enemyGuards/...` записуються, але не читаються — склад гарнізону в бою не збігається з розвідкою
- Великі sprite sheet'и (до 8000 px) імпортуються з `maxTextureSize: 2048` → втрата деталізації
